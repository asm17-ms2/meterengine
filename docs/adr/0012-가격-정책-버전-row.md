# 0012. 가격 정책 이력: 버전 row (변경은 INSERT)

- 상태: 승인
- 결정일: 2026-07-31 (MS2-40 착수 결정)
- 관련 이슈: MS2-26, MS2-40

## 맥락

단가를 바꿀 때 기존 row를 수정할지, 새 row를 발행할지 정해야 한다. 불변 결정 목록(2026-07-29 비준)이 확정한 불변식은 "단가를 어떤 방식으로 바꾸든 변경 전 값과 적용 시점이 복구 가능하게 남아야 한다. 이력 없는 덮어쓰기만은 금지"까지였고, 구체 방식은 MS2-40 착수 시 결정으로 이관되어 있었다. 이력이 없으면 "이 draft가 어느 단가로 계산됐는가"가 영구 소실된다.

## 결정

가격 정책은 버전 row 방식으로 이력을 보존한다.

- 단가 변경은 UPDATE가 아니라 새 row INSERT다
- 현재 유효 단가는 미터별 created_at 최신 행이고, 동률이면 id 내림차순 우선이다
- V1 스키마가 이미 이 구조를 수용하므로 마이그레이션은 없다
- effective_from 기반 시점 rating(occurred_at 시점의 단가 참조)은 이번에 도입하지 않고 후속 결정으로 남긴다. 도입 시에도 버전 row 이력에서 재구성 가능하다

## 근거

- 직접 수정은 이력이 소실되어 불변식을 위반한다. 복구 불가가 확정되는 유일한 선택지라 배제된다
- 별도 이력 테이블(수정 허용 + 이력 기록)도 이력은 남지만, 본 테이블과 이력 테이블 두 곳에 같은 지식이 생기고 draft 계산이 참조하는 대상이 모호해진다. 버전 row는 진실의 출처가 한 테이블이다
- MVP 매트릭스가 가격정책 버전 관리/소급을 P1(MVP 직후)로 등급했으므로, S1은 이력 보존이 성립하는 최소 구조(버전 row)까지만 가져가고 시점 rating은 미룬다

## 대안

- 단가 직접 수정: 이력 소실, 복구 불가. 불변식 위반으로 배제
- 수정 허용 + 별도 이력 테이블: 이력은 남지만 진실의 출처가 둘로 갈린다. 버전제 전환 시 재구성 비용도 버전 row와 다르지 않다
- effective_from 버전제 즉시 도입: 소급을 원천 차단하는 장점이 있지만 S1 범위를 넘는다. 버전 row 이력이 있으면 후속 도입 시 재구성 가능하므로 미룬다

## 전환 조건

- effective_from 시점 rating 도입 시점(가격 버전 관리 스토리 MS2-62 계열): 최초 버전의 effective_from을 최솟값 상당으로 두는 규칙(과거 백필 이벤트의 rating 실패 방지)을 함께 확정하고 새 ADR로 기록한다
- 정책 폐지 표현(tombstone)은 필요해지는 시점에 결정한다. 그 전까지 잘못 만든 정책은 운영 롤 수동 절차(0008)로 정리한다
