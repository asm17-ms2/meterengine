# 0007. 이벤트 귀속: 수신 시 식별자 해소와 미해소 이벤트 보존

- 상태: 승인
- 결정일: 2026-07-29 (데일리 비준)
- 관련 이슈: MS2-26

## 맥락

이벤트가 실어 오는 것은 도입사가 지은 이름 문자열(고객 external_customer_id, 미터 code)이다. 이름은 재사용될 수 있어(0011: 삭제 후 같은 이름 재등록 허용), 이름만 저장하면 과거 이벤트가 나중에 등록된 다른 고객의 사용량으로 둔갑한다. raw 이벤트는 불변(0008)이라 이 오귀속은 고칠 방법이 없는 영구 사고가 된다.

## 결정

수신 시점에 이름을 내부 UUID로 해소해, 원문 이름과 해소된 UUID(customer_id, meter_id)를 나란히 저장한다. UUID는 재발급되지 않으므로 이름이 재사용돼도 과거 이벤트의 귀속은 고정된다.

- 미등록 이름으로 온 이벤트는 거절하지 않고 UUID를 NULL로 저장한다. 미해소 이벤트는 집계에서 제외하고 건수로 노출한다(MS2-46). 형식이 틀린 요청(필수 필드 누락)은 4xx 거절, 형식은 맞는데 이름이 안 풀리는 이벤트는 보존이 경계선이다
- 재연결은 customer_id/meter_id의 NULL을 값으로 1회 채우는 것만 허용한다. DB가 강제한다: 앱 롤에는 이 두 컬럼에만 UPDATE 권한을 주고, 가드 트리거로 값 변경과 값 삭제를 거부한다
- v0의 late binding(청구 시점 매칭) 범위는 구독-charge 매칭으로 한정하고, 고객과 미터 해소는 수신 시점으로 앞당긴다. late binding이 보장하던 재처리 가능성은 위 빈칸 채움 규칙이 대신한다

## 근거

- 이름만 저장하는 안을 안전하게 만들려면 이름 재사용을 영원히 금지해야 하는데, UUID 해소는 도입사에게 아무 제약 없이 같은 안전을 얻는다
- 미등록 이벤트를 거절하면 그 이벤트는 영원히 유실된다. 저장해 두면 미터/고객 등록 뒤 다시 연결할 수 있다. Lago도 맞지 않는 이벤트를 거절하지 않고 수집 후 후처리에서 제외한다 (공식 문서 확인 2026-07-29)
- 재연결을 1회 빈칸 채움으로 제한하지 않으면 0008의 UPDATE 회수가 재연결 자체를 막아 미해소 이벤트가 영구 과소청구로 남는다

## 대안

- 이름만 저장: 재사용 금지를 함께 강제해야 성립한다. 도입사 제약이 생기고, 금지를 어기는 순간 오귀속 사고 구조가 된다
- 이름만 저장 + 재사용 허용: 오귀속 사고가 구조적으로 보장되는 조합이라 선택 불가

## 전환 조건

- 구독 도입 시 구독-charge 매칭의 late binding 설계를 별도 ADR로 정한다
- 미해소 이벤트가 상시 다량 발생하면(오타가 아니라 등록 선행 워크플로 문제) 등록 API 흐름을 재검토한다
