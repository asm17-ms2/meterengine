# ADR (Architecture Decision Record)

되돌리기 비싼 설계 결정을 기록한다. 무엇이 ADR감인지는 `docs/문서-관리-규칙.md`의 판별 순서(Q1)를 따른다. 결정 대상 예시: 수집 경로, 저장소 구성, 집계 방식, 기술 스택 (MS2-28).

## 작성

- 파일명: `NNNN-제목.md` (예: `0001-기술-스택.md`). 번호는 만든 순서대로 증가하고, 머지된 번호는 재사용하지 않는다
- 형식은 `template.md`를 따른다: 상태 / 결정 / 근거 / 대안 / 전환 조건
- 한 장은 1~2페이지, 작성 시간은 20분을 넘기지 않는다. 넘기면 둘 중 하나다. 결정이 실제로는 나지 않았거나(맥락을 쓰다가 막히면 대개 이 경우다), 애초에 ADR감이 아니었다
- 근거 마지막 줄에 미확인 사항을 적는다. 확인하지 못한 채로 결정했다는 사실 자체가 기록이다
- 슬라이스 진행 중 필요한 시점에 결정한다. 전 범위를 미리 결정하지 않는다

## 상태 전이

결정은 PR에서 한다. Slack이나 통화에서 결론을 내고 오면 채택된 안만 PR로 올라오고 기각된 안은 아무 데도 남지 않는다. 반년 뒤 같은 논의가 처음부터 재발한다.

- "제안" 상태로 PR을 올리고, 합의되면 같은 PR에서 상태를 "승인"으로 바꾸고 결정일을 기입한 뒤 머지한다. 머지 = 승인이다. "제안" 상태로 머지하지 않는다
- 결론이 이미 명백한 건은 "승인" 상태로 바로 올려도 된다. 리뷰어는 "제안"으로 되돌릴 것을 요청할 수 있다
- 승인된 ADR은 고치지 않는다. 결정이 뒤집히면 새 ADR을 만들고 양방향으로 잇는다: 새 ADR에 "NNNN을 대체함", 기존 ADR의 상태에 "대체됨(-> 새 번호)"

## 기각과 철회

팀이 판단했으면 기각, 작성자가 스스로 접으면 철회다.

- **기각**: PR을 닫지 않는다. 상태를 "기각"으로 바꾸고 근거에 사유를 적어 머지한다. 같은 논의가 재발하는 것을 막는 기록이다
- **철회**: PR을 닫는다. main에 남지 않으므로 그 번호는 다음 사람이 재사용한다

기각을 전부 남기지는 않는다. 아래 중 하나라도 해당하면 남긴다.

- 논의에 시간이 들었다
- 다시 제안될 가능성이 높다
- 기각 사유가 조건부다 (지금은 아니지만 나중에는 달라질 수 있다)
