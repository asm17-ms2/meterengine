# 0009. 시각 필드 의미론: occurred_at/received_at 분리, UTC 저장, KST 경계

- 상태: 제안
- 결정일: 2026-07-29 (데일리 비준, PR 머지 시 승인으로 변경)
- 관련 이슈: MS2-26

## 맥락

이벤트의 시각 필드를 몇 개 두고, 어느 타임존으로 저장하며, 집계와 귀속 계산은 무엇을 기준으로 하는지 정해야 한다. 시각 필드를 하나만 두면 발생과 수신의 간격이 소실되어 지연 도착을 영원히 감지할 수 없고, 지연 이벤트가 엉뚱한 달에 청구된다.

## 결정

occurred_at(발생)과 received_at(수신)을 분리해 둘 다 NOT NULL로 저장한다.

- 저장은 UTC로 정규화한다. 귀속과 표시의 날짜 경계는 KST 자정이다. 저장 타임존과 경계는 독립된 결정이다
- 모든 도메인 계산(집계, 기간 귀속, 가격 버전 참조)의 기준은 occurred_at이다
- occurred_at 누락은 4xx로 거절한다. received_at은 서버가 찍고 클라이언트 입력을 받지 않는다
- API 입력 형식(ISO 8601 오프셋 규칙 등)은 API 명세(MS2-27) 소관이다

## 근거

- 수신과 발생의 차이가 곧 지연이다. 분리 저장해야 지연 도착 처리 정책(후속 슬라이스)이 설 자리가 생긴다
- 저장과 표시를 분리해야 해외 고객과 서머타임에서 하루 경계가 어긋나지 않는다
- 수신 시점 귀속은 지연 이벤트를 받은 달에 붙여 버린다. occurred_at 귀속이라야 사용량이 발생한 기간에 청구된다
- 수신 시각의 진실 출처는 서버다. 클라이언트가 received_at을 조작할 수 있으면 지연 감지가 무의미해진다

## 대안

- timestamp 1개: 발생-수신 간격이 소실되어 지연 감지가 영원히 불가능하고, MS2-38 인수 조건("occurred_at과 received_at이 구분 저장된다")을 위반한다

## 전환 조건

- 해외 도입사가 생겨 KST 외 경계가 필요해지면 도입사별 타임존 설정을 검토한다. UTC 저장은 그대로 유효하므로 경계 규칙만 확장하면 된다
