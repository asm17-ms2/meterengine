# 0013. KRW 단수 처리: 절사, 라인아이템 단위 1회 (S1 임시 규칙)

- 상태: 제안
- 결정일: 2026-08-01 (팀 합의, PR 머지 시 승인으로 변경)
- 관련 이슈: MS2-40

## 맥락

기간 요금 = 집계값 x 단가 / 묶음 수량. 나눗셈이 있는 한 소수는 반드시 발생하고(1,900토큰 x "1,000토큰당 4원" = 7.6원), 청구액은 원 단위 정수여야 한다. 계산 구조(고정밀 중간 계산, 1회 처리, 규칙 격리, precise_amount 병행 저장)는 0010에서 확정했고, 규칙 선택은 그 구조 덕에 가역이라 MS2-40 착수 시 결정으로 이관되어 있었다.

## 결정

- 단수 규칙: 절사(버림). 1원 미만 단수는 버린다. 7.6원이면 7원이다
- 적용 지점: 라인아이템 단위, 정확히 1회. 미터별 라인아이템 금액을 각각 정수로 확정한 뒤 합산한다. 그 밖의 어느 지점에서도 반올림이나 절사를 하지 않으므로 "라인 금액의 합 = 총액"이 항상 성립한다
- 이것은 S1 임시 규칙이다. S2 정식 정책 "KRW 단수 처리와 계산 정밀도"(MS2-44)가 이 결정을 대체한다. 임시본과 최종본의 관계이지 경쟁하는 두 결정이 아니다

## 근거

- 절사는 청구액이 고객에게 불리해지지 않아 분쟁 소지가 최소이고, 국고금 규정(10원 미만 절사)과 방향이 같다
- 반올림도 합법이며 국세청 권장 방식이지만, 규칙 격리와 precise_amount 병행 기록(0010) 덕에 S2에서 반올림으로 바꿔도 상수 수정과 draft 재계산으로 끝난다
- 라인 단위 확정은 미터별 라인이 여러 개일 때 각 라인 요금을 독립 검증할 수 있고, 화면과 API와 검산이 일치한다. API 명세의 total_amount 정의("line_items[].amount의 단순 합")와 정합하다
- 단수 규칙을 문서화하는 것 자체가 차별점이다. 경쟁사 조사에서 9곳 중 단수 규칙을 완전히 문서화한 곳이 없었다

## 대안

- 반올림: 합법(국세청 권장)이고 오차 평균이 0에 가깝다. 가역 구조라 S2 정식 정책에서 재선택할 수 있으므로 지금은 분쟁 최소 쪽을 택한다
- 인보이스 총액 단위 확정: 누적 오차는 없지만 라인 합과 총액이 어긋날 수 있어 "합이 왜 안 맞죠" 문의를 유발한다

## 전환 조건

- S2 정식 정책(MS2-44) 확정 시 새 ADR로 대체하고 이 문서의 상태를 "대체됨"으로 바꾼다
- 도입사별, 가격정책별 규칙 설정 승격은 그 정식 정책에서 검토한다
