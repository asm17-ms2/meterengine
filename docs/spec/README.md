# 시스템 사양 (SPEC)

코드가 구현하는 값과 규칙의 정본이다. 여기 있는 값이 유일본이며, 다른 문서는 정본을 병기해 인용만 한다.

무엇을 여기 쓰고 무엇을 다른 곳에 쓰는지는 `docs/문서-관리-규칙.md`의 판별 순서를 따른다. 요약하면 값이 무엇인지는 여기, 왜 그 값인지는 `docs/adr/`, 사람이 무엇을 하는지는 Notion이다.

## 규칙

- 파일 하나가 주제 하나를 담는다 (멱등성, 시간 의미론, 보존, 에러 카탈로그)
- 값과 경계 조건을 표로 쓴다. 근거 열은 "왜 골랐나"가 아니라 "바꿔도 되나"에 답한다
- 근거가 세 줄을 넘으면 ADR로 올린다. 세 줄로 안 끝나는 근거는 값 옆에 둘 것이 아니다
- 관련 섹션에 구현과 테스트를 링크한다. 생략하지 않는다
- 값이 코드에 들어가면 상수 선언부 주석에 이 문서의 경로와 항목을 적는다. 링크는 양방향이어야 한다
- 슬라이스 착수 시점에 그 슬라이스에 필요한 범위만 확정한다. 미정 범위는 미정이라고 쓴다

## 문서 구조

```markdown
# 주제

## 규칙

| 항목 | 값 | 근거 / 변경 가능성 |
|---|---|---|

## 경계

값이 적용되지 않는 구간, 예외 처리, 만료 후 동작

## 관련

- 관련 ADR 번호와 제목
- 구현 클래스 / 테스트 클래스
```

## 현재 상태

현재 문서: `idempotency.md`(이벤트 멱등성), `event-ingestion.md`(이벤트 수신과 귀속), `money.md`(금액과 단가).
