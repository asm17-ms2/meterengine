# docs

팀의 결정과 규칙.

- `adr/`: 중요한 아키텍처 결정의 배경, 이유와 결과. 쓰는 법은 adr/README.md.
- `rfcs/`: 기존 RFC 기록. 내용과 번호, 당시 이유를 보존한다.
- `policies/`: 제품과 업무의 처리 조건, 예외와 적용값. 도메인당 파일 하나, 동작을 바꾸면 코드와 같은 PR로 반영한다. 쓰는 법은 policies/README.md.
- `contributing/`: 팀 규칙. 주제당 파일 하나. 입구는 CONTRIBUTING.md.
- 여기에는 위 디렉터리만 둔다. 무엇을 어디에 두고 어떻게 바꾸는지는 contributing/governance.md.
