# docs

코드가 원인인 문서를 둔다. 코드와 같은 PR에서 리뷰하고 git 이력으로 버전을 관리한다.

| 폴더 | 내용 | 관련 이슈 |
| --- | --- | --- |
| `adr/` | 아키텍처 결정 기록 | MS2-28 |
| `api/` | OpenAPI 명세 | MS2-27 |
| `erd/` | 도메인 모델, ERD | MS2-26 |

## 여기 두지 않는 것

합의가 원인인 문서는 Notion의 MS2 팀 위키가 정본이다: 제품 정의, 슬라이스 시퀀스, 릴리스 라인, 정책(절사 방식 같은 정밀 규칙 포함), 회의록.

정책의 정밀 규칙은 이 레포에 복사하지 않는다. 테스트가 Notion 정책 항목 번호를 참조해 고정하고, 정책 변경은 Notion 합의 -> 테스트/코드 반영 순서로 진행한다.

## 작성 규칙

- 모든 문서는 living document다. 슬라이스 착수 시점에 그 슬라이스 범위만 확정하고, 구현에서 배운 것을 반영해 버전을 올린다
- 문서 상단에 버전과 반영 범위(어느 슬라이스까지 반영했는지)를 명시한다
- 미정 범위를 확정된 것처럼 서술하지 않는다. "미정(착수 시 확정)"을 명시한다
