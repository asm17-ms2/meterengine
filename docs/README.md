# docs

코드가 원인인 문서를 둔다. 코드와 같은 PR에서 리뷰하고 git 이력으로 버전을 관리한다.

**새 문서를 만들기 전에 [문서 관리 규칙](문서-관리-규칙.md)의 판별 순서를 본다.** 문서 종류별 위치와 토론 장소도 거기에 있다.

| 폴더 | 내용 | 관련 이슈 |
| --- | --- | --- |
| `spec/` | 시스템 사양. 코드가 참조하는 값과 규칙 | |
| `adr/` | 아키텍처 결정 기록 | MS2-28 |
| `api/` | OpenAPI 명세 | MS2-27 |
| `erd/` | 스키마와 ERD (생성물) | MS2-26 |

## 작성 규칙

- 모든 문서는 living document다. 슬라이스 착수 시점에 그 슬라이스 범위만 확정하고, 구현에서 배운 것을 반영해 버전을 올린다
- 문서 상단에 버전과 반영 범위(어느 슬라이스까지 반영했는지)를 명시한다. `erd/`는 예외다 (생성물이라 DB의 현재 상태를 반영한다)
- 미정 범위를 확정된 것처럼 서술하지 않는다. "미정(착수 시 확정)"을 명시한다
