# 정책

RFC가 정한 방향 안에서 실제로 적용되는 규칙과 값을 도메인별로 적는 폴더입니다.
값은 정책 파일이 정하고 코드가 적용합니다. 여기에는 값, 그 값이 사는 코드 위치, 왜 그런지를 적습니다. 둘이 다르면 둘 중 하나가 버그입니다.

## 쓰는 법

1. 도메인 파일이 없으면 `template.md`를 복사해 `<백엔드 패키지명>.md`로 만든다 (customer, event, metric, pricing, invoice, payment).
2. 주제마다 절 하나, 규칙 하나가 표 한 줄. 값, 코드 위치(클래스.상수, 메서드, 테스트 이름, DB 제약 이름, openapi.yaml 스키마 이름), 근거를 적고 표 아래에 왜 그 값인지 한 줄을 붙인다. 코드 위치는 그 값을 단언하는 테스트 이름을 우선해 적고, 그런 테스트가 없으면 그 PR에서 만든다. 상수 이름만 적으면 값이 조용히 바뀌어도 아무것도 실패하지 않는다. 근거는 커밋이나 PR 번호를 먼저 쓰고, 없으면 초기 관례라고 쓴다. 담당자, 상태, 버전 열은 두지 않는다. 변경 이력은 git log가 대신한다.
3. 값을 바꿀 때는 코드와 같은 PR에서 이 파일을 고친다. 리뷰어는 코드 위치가 실제로 grep되는지 확인한다.
4. 바꾸면 외부 계약이나 쌓인 데이터가 같이 움직이는 것은 정책이 아니라 RFC다. 기준은 `docs/contributing/governance.md` "가르는 기준".
