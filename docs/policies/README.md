# 정책

제품과 업무의 처리 조건, 예외와 적용값을 도메인별로 관리한다.

- 합의한 정책을 문서에 기록하고 코드가 적용한다. 기대 동작과 코드가 다르면 둘 중 하나가 버그다.
- 정책은 어떤 조건에서 처리를 허용하거나 차단하는지, 예외를 어떻게 처리하는지와 적용할 값을 포함한다. 내부 구현 세부는 코드가 정본이라 여기 적지 않는다.
- 사전 합의와 ADR의 대상은 `docs/contributing/governance.md`의 "사전 합의"와 "가르는 기준"을 따른다.
- API 계약에 포함된 내용은 `backend/openapi.yaml`이 정본이다. 절 첫머리에 어느 description이나 스키마인지 가리키고 같은 내용을 표에 옮겨 적지 않는다.

## 쓰는 법

1. 도메인 파일이 없으면 `template.md`를 복사해 `<백엔드 패키지명>.md`로 만든다.
2. 주제마다 절 하나, 정책 항목마다 표 한 줄. 처리 조건, 예외와 적용값 중 해당하는 내용과 코드 위치를 적는다. API 계약과 중복되는 내용은 정본을 연결한다.
   - 코드 위치는 그 정책의 기대 동작을 단언하는 테스트 이름을 우선한다. 없으면 해당 동작을 바꾸는 PR에서 만든다.
   - 왜 그 정책인지는 커밋 본문에 적는다. 정책을 다시 볼 조건이 있으면 표 아래 "재검토 조건:" 한 줄.
   - 근거, 담당자, 상태, 버전 열은 두지 않는다.
3. 동작을 바꾸는 정책 변경은 사전 합의 후 코드와 같은 PR에서 반영한다. 의미를 보존하는 표현이나 링크 정리는 문서 PR로 진행한다. 리뷰어는 코드 위치가 grep되는지 확인한다.
4. 아키텍처에 중요한 영향을 주는 설계 선택이 포함되면 `docs/contributing/governance.md`의 기준에 따라 ADR을 작성해 연결한다.
