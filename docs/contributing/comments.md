# 주석과 javadoc

- 주석을 쓰지 않는다. javadoc도 주석이다.
  - 예외는 선언 바로 위의 한 줄 설명뿐이다.
  - 구조로 강제할 규칙은 주석이 아니라 아키텍처 테스트나 CI 검사로 넣는다.
  - 주석을 붙이고 싶어지면 이름이나 분리를 고친다.

## 한 줄 설명

- 의무가 아니다. 코드만으로 읽기 불편한 자리에 가볍게 붙인다.
- 함수, 필드, 상수 바로 위에 무엇을 하는지 한 문장으로 적는다(`// 고객을 등록한다.`).
  - 왜는 적지 않는다.
  - 옆의 목록이나 코드를 세어 개수를 적지 않는다.
  - 다른 파일의 주석을 가리키지 않는다.
  - 코드에 없는 사실(실측값, 성능, 외부 시스템의 동작)을 적지 않는다.
  - 함수 본문 안에는 쓰지 않는다. 본문을 설명하고 싶으면 함수를 쪼갠다.

## 주석이 아닌 것

- 도구 지시문: `@SuppressWarnings`, `// eslint-disable-next-line`. 억제 이유는 덧붙이지 않는다.
- `@Schema`, `@Operation`, `@Parameter`, `@ApiResponse`의 description. API 계약이라 `backend/openapi.yaml`로 나간다. Jira 키는 넣지 않는다.
- 파일을 나누는 구분자: `// --- 등록 ---`. 레이블은 명사구 한 줄이다.

## 주석 대신 쓰는 곳

| 쓰고 싶은 것 | 가는 곳 |
| --- | --- |
| 왜 이렇게 설계했는지 | 결정이면 `docs/rfcs/`, 값이면 `docs/policies/`. 이유는 커밋 본문 |
| 이 변경을 왜 했는지 | 커밋 메시지와 PR 본문 |
| 고치면 깨진다, 이 제약을 지켜야 한다 | 테스트 |

## 규칙 이전의 주석 (한시 규칙)

- 일괄 삭제 PR이 머지되면 이 절을 지운다.
- 규칙 이전의 주석과 javadoc은 레포 전체를 한 PR로 지운다. 마이그레이션의 `R__` 시드까지 포함한다.
  - 지운 내용을 정책이나 RFC로 옮기지 않는다.
  - 규칙에 맞는 한 줄 설명은 남긴다. 긴 주석을 한 줄로 줄이거나 새 설명을 붙이지 않는다.
  - 지우는 심볼을 가리키는 다른 파일의 문장도 같은 PR에서 처리한다.
- `V__`는 주석만 지워도 체크섬이 바뀐다. 같은 PR에서 배포 서버의 DB와 각자 로컬 볼륨의 체크섬을 맞춘다.
  - `R__`는 체크섬이 바뀌면 다음 기동 때 다시 실행된다. 다시 실행돼도 되는지 확인한다.
  - CI는 매번 빈 DB라 둘 다 잡지 못한다.
- 기존 파일의 주석 밀도는 본보기가 아니다.
