# 문서 공통 규칙

- 레포 안의 모든 문서에 적용한다. README, 규칙 파일, 정책 파일, CLAUDE.md, 용어집.
  - RFC 본문은 머지된 뒤 고치지 않으므로 대상이 아니다. 새 RFC는 `docs/rfcs/template.md`를 따른다.
- 문서 규칙은 사람의 부담을 줄이려는 것이다. 문서가 빠져도 코드는 그대로 돌고, 빠진 것은 다음 PR로 더한다.

## 정본은 하나

- 한 내용을 두 곳에 쓰지 않는다. 정본이 아닌 곳에서는 정본을 가리킨다. 정본은 `governance.md` "정본".
- README와 CLAUDE.md는 규칙을 베끼지 않고 규칙 파일을 가리킨다.
- RFC와 규칙 파일이 겹치는 것은 중복이 아니다. RFC는 머지되는 순간 얼어붙는 제안서다.

## 읽기 쉽게

- 사람이 한 번 읽고 이해되게, 짧고 명시적으로 쓴다.
  - 이유와 배경은 적지 않는다. 커밋 본문에 있다.
  - 예시는 하나만.
- 불릿으로 쓴다. 산문 문단은 쓰지 않는다.
  - 불릿 하나에 내용 하나. 조건, 예외, 예시는 하위 불릿.
  - 모든 불릿은 마침표로 끝낸다.
  - 제목 바로 아래 한 문장 소개는 문단으로 둬도 된다. 루트 README의 소개는 대외 README 관례대로 짧은 문단 몇 개까지.
  - 열거형 정보는 표.
- 규칙 문서는 미리 완벽하게 쓰지 않는다. 빠진 규칙은 PR에서 드러나면 그때 더한다.
- 금지 문자: 가운뎃점, 엠 대시, 엔 대시, 이모지, 둥근 따옴표. 하이픈, 쉼표, 콜론, 곧은 따옴표로 대체한다. 공식 고유명사는 예외.
- 실행 절차를 적는 README는 명령을 위에서부터 복사해 붙이면 도는 꼴로 쓴다.

## 문서를 옮기거나 양식을 바꿀 때

- 빠짐없이 옮겨졌는지는 작성자와 도구(Claude)가 대조한다. 리뷰어는 합의한 규칙에서 빠진 것이 없는지만 훑는다.
- 도구는 중대한 내용이 빠지지 않았는지 확인한다. 사소한 것이라도 빠뜨리게 되면 사용자에게 보고하고 확인한다.

## 시간이 지나면 틀리는 값

- 레포 안의 파일은 지금 상태를 서술한다. 세상이 움직여도 아무것도 실패하지 않는 값은 쓰지 않는다.
- 쓸 수 있는 숫자는 값이 바뀌면 뜻이 바뀌는 것뿐이다.
  - 닫혀 있다는 주장: "열린 포트는 80과 443뿐이다".
  - 규칙에 박힌 값: "상한은 300줄이다".
  - 과거 사례("당시 고객 CRUD 1593줄")는 기록이라 그대로 둔다.
- 외부 시스템의 상태는 "2026-08 기준"처럼 시점을 붙인다.
- 코드 안의 주석은 같은 이유로 쓰지 않는다. `comments.md`.

### Jira 키

- Jira 키는 브랜치명, 커밋 메시지, PR 제목과 본문에만 쓴다. 레포 안의 파일에는 쓰지 않는다.
  - `@Schema`와 `@Operation`의 description에는 특히 넣지 않는다. `backend/openapi.yaml`로 외부에 나간다.
- 키를 지우는 것으로 끝내지 않는다. "MS2-xxx 예정이다"는 "아직 없다"로 다시 쓴다.
- 기존 표기는 그 파일을 다른 이유로 편집할 때 함께 뺀다.

### 개수 표현

- 옆에 목록이 있으면 그 개수를 문장이나 제목에 적지 않는다. 항목이 늘면 숫자가 조용히 틀린다.
- 코드 안의 한 줄 설명에도 적용한다.

| 자리 | 이렇게 쓰지 않는다 | 이렇게 쓴다 |
| --- | --- | --- |
| 표나 목록의 제목 | 예외 핸들러 넷 | 예외 핸들러 |
| 목록을 여는 문장 | 아래 셋 중 하나일 때 쓴다 | 아래 중 하나일 때 쓴다 |
| 목록을 닫는 문장 | 빼고 세는 것은 둘뿐이다 | 빼고 세는 것은 아래뿐이다 |
| 한 문장 안에 나열할 때 | `backend`, `frontend` 두 job이다 | `backend`, `frontend` job이다 |

- 문서가 정하거나 약속하는 값("상한은 300줄이다", "본인 외 1명 이상 승인")은 그대로 쓴다.
- 기존 표현은 그 파일을 다른 이유로 편집할 때 함께 고친다.

## README 점검

- PR을 올리기 전에 아래 표에서 자기 변경이 해당하는 줄만 본다.

| 이번 PR에서 한 일 | 같이 볼 곳 |
| --- | --- |
| 프론트 화면을 추가하거나 자리표시자를 실제 화면으로 바꿨다 | `frontend/README.md`의 "화면" 표 |
| 마이그레이션이나 시드를 추가/변경했다 | `backend/README.md`의 마이그레이션 항목 |
| 컨트롤러나 DTO를 건드렸다 | `backend/README.md`의 API 문서 절. 생성물 `backend/openapi.yaml`은 CLAUDE.md의 규칙을 따른다 |
| 오류 code를 추가/변경했거나 오류 응답 형식을 건드렸다 | `backend/README.md`의 오류 응답 절 |
| 실행 명령이나 사전 준비(런타임 버전, 컨테이너)가 바뀌었다 | 루트 README "시작하기"와 해당 하위 README의 "실행" |
| 배포 구성이나 절차를 바꿨다 (compose, Caddy, 배포 스크립트, CD 워크플로) | `deploy/README.md` |
| CI 워크플로를 추가했거나 트리거를 바꿨다 | `.github/README.md`의 워크플로 표. 필수 체크면 `pull-request.md` "머지 조건" |
| 정책 값이나 그 코드 위치를 바꿨다 | 그 도메인의 `docs/policies/` 파일. 코드와 같은 PR에서 고친다 |
| RFC를 채택, 기각, 대체했다 | `docs/rfcs/README.md` 표의 상태와 날짜 |
| 가리키던 Jira 이슈가 닫혔다 | 그 이슈 키가 적힌 README 줄. 결정이 났으면 결정 내용을 쓰고, 안 났으면 미정이라고만 남긴다 |
