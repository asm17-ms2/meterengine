# 시간이 지나면 틀리는 값

레포 안의 파일은 지금 상태를 서술한다. 커밋 메시지와 PR은 과거의 기록이라 시간이 지나도 참이지만, 레포 안의 문장은 세상이 움직이면 같이 움직여야 한다. 움직여도 아무것도 실패하지 않는 값은 직접 확인하기 전까지 아무도 틀린 줄 모른다. 그런 값은 쓰지 않는다. 아래 절이 그 사례다.

쓸 수 있는 숫자는 값이 바뀌는 것이 곧 뜻이 바뀌는 것일 때다. 닫혀 있다는 주장("열린 포트는 80과 443뿐이다"), 규칙에 박힌 값("상한은 300줄이다"). 과거 사례를 보여 주는 예시("당시 고객 CRUD 1593줄을 이렇게 잘랐다")는 기록이라 그대로 둔다. 외부 시스템의 상태를 적어야 하면 "2026-08 기준 public preview"처럼 시점을 붙여 낡을 수 있다는 것을 드러낸다.

## Jira 키

Jira 키는 **브랜치명, 커밋 메시지, PR 제목과 본문**에만 쓴다. 레포 안의 파일에는 쓰지 않는다.

이들은 과거의 기록이라 시간이 지나도 참이다. 반면 레포 안의 파일은 지금 상태를 서술하므로, 외부 시스템의 상태를 박아 넣으면 그 티켓이 움직일 때 문서만 조용히 틀려진다. 주석을 쓰지 않는 이유와 같다.

브랜치명의 키는 Jira 자동 연결에 쓰이므로 티켓이 있으면 반드시 넣는다. 티켓 없이 가는 작업만 위 "티켓 없이 가는 작업"대로 뺀다.

`@Schema`와 `@Operation`의 description에는 특히 넣지 않는다. `backend/openapi.yaml`로 생성되어 프론트엔드와 외부가 읽으므로, 내부 티켓 키가 그대로 나간다.

키를 지우는 것으로 끝내지 않는다. "단가 등록은 MS2-xxx 예정이다" 같은 문장은 "단가 등록은 아직 없다"로 다시 쓴다. 읽는 사람이 알아야 할 것은 지금 없다는 사실이지 티켓 번호가 아니다. 어느 티켓에서 온 문장인지는 `git blame`이 그 줄의 커밋 메시지로 데려다준다.

레포 밖 도구(Miro, Jira)는 대상이 아니다. 티켓 추적은 원래 그쪽 몫이다.

지금부터 새로 쓰는 것에 적용한다. 기존 표기는 그 파일을 다른 이유로 편집할 때 함께 뺀다. 문장 하나를 고치는 일이라 주석과 달리 PR을 따로 열지 않는다.

## 문서의 개수 표현

**옆에 목록이 있으면 그 개수를 문장이나 제목에 적지 않는다.** 항목이 늘거나 줄면 숫자는 조용히 틀린다. 주석과 같은 방식으로 썩는다. 아무것도 실패하지 않고, 직접 세어 보기 전까지 아무도 모른다.

"예외 핸들러 넷"이라는 제목 아래에 핸들러 표가 있다고 하자. 표가 이미 목록인데 제목이 개수를 한 번 더 말한다. 핸들러를 붙이는 사람이 표만 고치고 제목을 지나치면 그때부터 문서가 틀린 말을 한다. 제목을 "예외 핸들러"로 두면 표가 곧 목록이라 틀릴 자리가 없다.

| 자리 | 이렇게 쓰지 않는다 | 이렇게 쓴다 |
| --- | --- | --- |
| 표나 목록의 제목 | 예외 핸들러 넷 | 예외 핸들러 |
| 목록을 여는 문장 | 아래 셋 중 하나일 때 쓴다 | 아래 중 하나일 때 쓴다 |
| 목록을 닫는 문장 | 빼고 세는 것은 둘뿐이다 | 빼고 세는 것은 아래뿐이다 |
| 한 문장 안에 나열할 때 | `backend`, `frontend` 두 job이다 | `backend`, `frontend` job이다 |

### 숫자가 내용인 자리

값이 바뀌는 것이 곧 뜻이 바뀌는 것이면 그대로 쓴다.

- 닫혀 있다는 주장: "인터넷에 열린 포트는 80과 443뿐이다"
- 규칙에 박힌 값: "상한은 300줄이다", "본인 외 1명 이상 승인"

지금 상태를 세어 적은 값은 목록이 옆에 없어도 쓰지 않는다. 지킬 목록이 없어 값이 움직여도 아무도 모른다. 가르는 기준은 그 숫자를 문서가 정하거나 약속하느냐, 세상을 재서 옮겨 적었느냐다. 앞의 것은 바꾸려면 문서를 고쳐야 하고, 뒤의 것은 세상이 움직이면 문서만 낡는다.

### 적용 시점

지금부터 새로 쓰거나 고치는 문서에 적용한다. 기존 표현을 한꺼번에 걷어내지 않고, 그 파일을 다른 이유로 편집할 때 함께 고친다.

## README 점검

README는 슬라이스가 끝날 때마다 조금씩 밀린다. "아직 없다"고 적힌 것이 이미 있고, "그 이슈에서 정한다"고 가리킨 이슈가 닫혀 있는 식이다. 한 번에 몰아서 고치지 않으려면 PR을 올리기 전에 아래를 본다. 자기 변경이 해당하는 줄만 보면 된다.

| 이번 PR에서 한 일 | 같이 볼 곳 |
| --- | --- |
| 프론트 화면을 추가하거나 자리표시자를 실제 화면으로 바꿨다 | `frontend/README.md`의 "화면" 표 |
| 마이그레이션이나 시드를 추가/변경했다 | `backend/README.md` 기술 스택의 Flyway 항목 |
| 컨트롤러나 DTO를 건드렸다 | `backend/README.md` "API 문서"의 오퍼레이션 표. 생성물 `backend/openapi.yaml`은 CLAUDE.md의 규칙을 따른다 |
| 오류 code를 추가/변경했거나 오류 응답 형식을 건드렸다 | `backend/README.md` "오류 응답"의 code 목록. 값의 정본은 `ErrorCodes`이고, 프론트엔드는 모르는 code에 기본 문구를 쓴다 |
| 실행 명령이나 사전 준비(런타임 버전, 컨테이너)가 바뀌었다 | 루트 README "시작하기"와 해당 하위 README의 "실행" |
| 배포 구성이나 절차를 바꿨다 (compose, Caddy, 배포 스크립트, CD 워크플로) | `deploy/README.md`. 서버에서 도는 것이 바뀌면 "구성"도 같이 본다 |
| 정책 값(`docs/policies/`에 적힌 값)이나 그 코드 위치를 바꿨다 | 그 도메인의 `docs/policies/` 파일. 코드와 같은 PR에서 고친다 |
| RFC를 채택, 기각, 대체했다 | `docs/rfcs/README.md` 표의 상태와 날짜 |
| 가리키던 Jira 이슈가 닫혔다 (완료든 취소든) | 그 이슈 키가 적힌 README 줄. 결정이 났으면 결정 내용을 쓰고, 안 났으면 이슈 키를 떼고 미정이라고만 남긴다 |

닫힌 이슈를 가리키는 문장이 제일 오래 남는다. 읽는 사람이 그 이슈를 열어 봐도 답이 없어서다.
