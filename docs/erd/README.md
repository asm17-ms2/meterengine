# 스키마와 ERD

DB 스키마 문서를 둔다 (MS2-26). 스키마 변경의 입구는 Flyway 마이그레이션이며, 이 폴더의 문서를 고쳐서 스키마를 바꾸는 경로는 없다.

## 지위 (전환 중)

tbls로 실제 DB에서 생성하는 방식으로 전환하고 있다. 전환이 끝나면 이 폴더는 생성물 전용이 되고 직접 편집하지 않는다.

- 생성물에는 버전을 붙이지 않는다. DB의 현재 상태를 그대로 반영하므로 "어느 슬라이스까지 반영했는가"라는 질문이 성립하지 않는다. `docs/`의 다른 폴더에 적용되는 버전과 반영 범위 명시 규칙은 여기에 적용되지 않는다
- `erd.md`는 전환 전까지 수기 정본이다. 생성물이 대체하지 못하는 구간(제약 표의 근거 열, 의도된 제외, 스토리별 이관 항목)은 `docs/spec/`과 `docs/adr/`로 이관한다. 이관 대기 목록은 `docs/문서-관리-규칙.md`에 있다

## 새 제약을 정할 때

값은 `docs/spec/`, 근거는 `docs/adr/`에 쓴다. 판별은 `docs/문서-관리-규칙.md`의 Q1과 Q3을 따른다. 마이그레이션 SQL 주석에는 무엇을 하는지가 아니라 어느 문서가 근거인지를 적는다.

## 현재 상태

- `erd.md`: S1 ERD v2.2 (전환 전 수기 정본). mermaid 다이어그램 + 제약 표 + 스토리별 이관 항목
- S1 확정분의 DB 반영은 `backend/src/main/resources/db/migration/V1__create_s1_core_tables.sql`
