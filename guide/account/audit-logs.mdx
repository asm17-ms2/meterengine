<Note>
이 기능은 콘솔에 로그인한 상태에서만 됩니다. API 키로 부르면 거절됩니다.
</Note>

'감사 기록' 화면은 조직에서 일어난 업무 변경과 API 요청 결과를 시각순으로 보여 줍니다. 조회(read) 권한이 있는 구성원이 볼 수 있습니다.

## 남는 기록

| 기록 | 화면의 '활동' 예 | 실행 주체 |
| --- | --- | --- |
| 업무 변경 | '고객 등록', '미터 수정', '단가 버전 등록', '청구서 확정', '결제 요청', '결제 취소', '웹훅 URL 등록', 'API 키 발급', 'API 키 권한 변경', 'API 키 폐기' | 변경한 구성원 또는 'API 키' |
| 계정과 조직 | '로그인', '로그아웃', '사용자 계정 생성', '초대 링크 발급', '초대 수락', '역할 변경', '사용자 업무 권한 변경', '약관 동의', '라이브 환경 이용 신청' | 구성원 |
| API 요청 | 'API 요청'. 메서드와 경로, HTTP 상태가 함께 보입니다 | 요청한 구성원 또는 'API 키' |
| 고객 화면 | '고객 청구서 조회', '고객 결제 재시도 요청', '카드 등록' | '청구서 조회 링크' 또는 '시스템' |

- 조회 요청도 'API 요청'으로 남습니다. 화면을 새로 열 때마다 기록이 늘어납니다.
- 4xx와 5xx로 끝난 요청은 '요청 거절/오류'로 표시됩니다.
- 라이브 환경 이용 신청의 승인과 거절처럼 MeterEngine이 한 일은 실행 주체가 'MeterEngine'으로 보입니다.

### 남지 않는 요청

- 이벤트 수집 요청(`POST /v1/events`, `POST /v1/event-batches`). 저장된 이벤트와 수집 거절 기록의 `request_id`, `transaction_id`로 찾습니다([오류 응답과 X-Request-ID](/api-basics/errors)).
- 키 없이 보냈거나 틀린 키로 보내 401이나 429를 받은 요청

## 업무 환경별로 보이는 범위

감사 기록은 업무 환경마다 따로 보입니다. 테스트 키(`me_test_`)로 보낸 요청은 '테스트 환경'에서, 라이브 키(`me_live_`)로 보낸 요청은 '라이브 환경'에서 찾습니다.

로그인, 구성원, 초대, 사용자 업무 권한, 라이브 환경 이용 신청처럼 조직 공통인 기록은 어느 업무 환경에서 열어도 함께 보입니다. 환경마다 나뉘는 것은 [업무 환경](/concepts/environments)을 참고하세요.

## 기록 찾기

<Steps>
<Step title="업무 환경을 맞춥니다">
콘솔에 로그인한 뒤 화면 위 '업무 환경'을 찾을 기록의 환경으로 고릅니다.
</Step>
<Step title="조건을 넣습니다">
왼쪽 메뉴에서 '감사 기록'을 엽니다. '기록 찾기'에서 조건을 넣고 '조건 적용'을 누릅니다.

| 조건 | 넣는 값 |
| --- | --- |
| 활동 또는 대상 검색 | 응답 헤더 `X-Request-ID` 값, API 경로, 대상 ID, 활동 코드. 일부만 넣어도 찾습니다. 경로는 ID 자리가 `{id}`로 남으므로 `/v1/invoices`처럼 앞부분만 넣고, ID는 따로 넣습니다 |
| 실행 주체 | 로그인 사용자, API 키, 시스템, 미인증 요청, 청구서 조회 링크 |
| 활동 | '청구서 확정', 'API 키 폐기' 같은 활동 하나 |
| 시작 일시 (KST), 종료 일시 (KST, 미포함) | 찾을 기간. 종료 일시는 시작 일시보다 뒤여야 합니다 |
</Step>
<Step title="기록을 펼칩니다">
기록을 누르면 실행 주체, 대상, 활동 코드와 상세 값(JSON)이 보입니다. 'API 요청' 기록의 상세 값에는 `method`, `route`, `status`, `duration_ms`, `request_id`가 있습니다.
</Step>
</Steps>

<Tip>
오류 응답을 받으면 `X-Request-ID`를 자사 로그에 남겨 두세요. 그 값을 '활동 또는 대상 검색'에 넣으면 같은 요청의 기록을 바로 찾습니다.
</Tip>

감사 기록은 화면에서 지우거나 고칠 수 없습니다.
