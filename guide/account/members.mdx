<Note>
이 기능은 콘솔에 로그인한 상태에서만 됩니다. API 키로 부르면 거절됩니다.
</Note>

구성원은 콘솔에 로그인해 도입사 업무를 하는 도입사 직원입니다. 구성원은 콘솔의 '사용자 관리' 화면에서 관리합니다. 사용자와 초대 관리는 대표관리자만 할 수 있고, 다른 구성원에게는 "사용자 추가와 권한 변경은 대표관리자에게 요청하세요." 안내가 보입니다.

## 역할과 업무 권한

구성원마다 도입사 역할과 업무 권한이 있습니다.

| 도입사 역할 | 업무 권한 | 할 수 있는 일 |
| --- | --- | --- |
| 대표관리자 | 전체 관리 (admin) | 모든 도입사 업무와 사용자, 초대 관리 |
| 관리자 | 전체 관리 (admin) | 모든 도입사 업무. 사용자와 초대 관리는 못 합니다 |
| 일반 사용자 | 조회 (read), 수집 (ingest) 가운데 하나 또는 둘 | 받은 권한 안의 업무 |

- 조회 (read)는 고객, 사용량과 청구 내역을 봅니다. 수집 (ingest)은 고객 등록과 사용량 이벤트 전송을 합니다. 전체 관리 (admin)는 조회와 수집을 포함하고 그 밖의 데이터 변경도 합니다. 권한별로 허용되는 요청은 [화면과 API, 권한](/authentication/scopes)을 보세요.
- 역할은 업무 권한을 따라갑니다. 일반 사용자에게 전체 관리 (admin)를 주면 관리자가 되고, 관리자의 권한에서 전체 관리 (admin)를 빼면 일반 사용자가 됩니다.
- 조회 (read) 권한이 없는 구성원은 콘솔에서 업무 화면을 볼 수 없고 '업무 조회 권한이 없습니다' 안내를 봅니다.
- 도입사 계정과 권한은 업무 환경에 관계없이 같습니다. 테스트 환경에서 준 권한이 실제 환경에도 그대로 적용됩니다. 환경마다 따로인 것은 [업무 환경](/concepts/environments)을 보세요.
- 구성원의 권한과 API 키의 권한은 따로 관리합니다. 구성원 권한을 바꿔도 그 사람이 발급한 API 키의 권한은 바뀌지 않습니다.

초대 링크와 계정 직접 생성 모두 구성원을 추가할 때 기본 권한은 조회 (read)입니다. 필요한 권한을 골라 추가하세요.

## 구성원 추가하기

구성원은 초대 링크로 추가하거나 계정을 직접 만들어 추가합니다. 두 방법 모두 '사용자 관리' 화면의 '함께 일할 사용자 추가'에 있습니다.

| 방법 | 쓰는 경우 | 비밀번호를 정하는 사람 |
| --- | --- | --- |
| 초대 링크 만들기 | 초대할 사람이 직접 계정을 만들거나, 이미 MeterEngine 계정이 있는 경우 | 초대받은 사람 |
| 계정 직접 생성 | 대표관리자가 계정을 만들어 로그인 정보를 전달하는 경우 | 대표관리자가 초기 비밀번호를 정하고, 본인이 첫 로그인 때 바꿉니다 |

이미 MeterEngine 계정이 있는 이메일은 계정 직접 생성을 쓸 수 없습니다(`409 email_already_exists`). 그 사람은 초대 링크로 추가하세요.

### 초대 링크로 추가하기

MeterEngine은 초대 메일을 보내지 않습니다. 대표관리자가 링크를 복사해 초대할 사람에게 직접 전달합니다.

<Steps>
<Step title="초대 링크를 발급한다">
'사용자 관리' 화면의 '초대 링크 만들기'에서 '초대할 이메일'과 '업무 권한'을 정하고 '초대 링크 발급'을 누릅니다.
</Step>
<Step title="링크를 복사한다">
발급하면 '초대 링크 열기'와 '초대 링크 복사'가 한 번만 나옵니다. 닫기 전에 '초대 링크 복사'를 눌러 복사하세요. 닫으면 링크를 다시 볼 수 없고, '초대 이력' 목록에도 링크는 나오지 않습니다. 링크는 `https://meterengine.com/organization-invitations/me_invite_` 로 시작합니다.
</Step>
<Step title="초대할 사람에게 직접 전달한다">
메신저 등으로 초대할 사람에게만 보내세요. 링크는 발급 뒤 48시간 동안 지정한 이메일로 한 번만 수락할 수 있습니다.
</Step>
</Steps>

<Warning>
같은 이메일로 다시 발급해도 이전 링크는 취소하기 전까지 유효합니다. 링크를 잃었거나 잘못 보냈다면 '초대 이력'에서 이전 초대를 먼저 '초대 취소'한 뒤 새로 발급하세요. 계정이 없는 이메일로 보낸 링크는 받은 사람이 그 자리에서 계정을 만들 수 있으니 초대할 사람에게만 보내세요.
</Warning>

이미 이 도입사에 소속된 사용자의 이메일로는 초대 링크를 발급할 수 없습니다(`409 organization_member_already_exists`).

### 초대받은 사람이 하는 일

초대받은 사람은 링크를 열면 '(도입사 이름)에 참여' 화면에서 참여 권한과 수락 기한(KST)을 봅니다. 그다음은 계정이 있는지에 따라 다릅니다.

<Tabs>
<Tab title="MeterEngine 계정이 없을 때">
<Steps>
<Step title="계정 정보를 넣는다">
'이름', '비밀번호'를 넣습니다. 비밀번호는 8자 이상 72자 이하이고 한글은 1자를 3자로 계산합니다. 이메일은 초대받은 이메일로 정해져 있습니다.
</Step>
<Step title="필수 동의에 체크한다">
'이용 안내'와 '개인정보 처리 안내'에 모두 체크합니다. 동의 내용은 [가입과 승인](/account/signup)의 필수 동의와 같습니다.
</Step>
<Step title="수락한다">
'초대 수락하고 도입사로 이동'을 누르면 계정이 만들어지고 로그인된 채로 그 도입사의 '개요' 화면으로 이동합니다.
</Step>
</Steps>

다른 계정으로 로그인한 브라우저에서 이 링크를 열면 현재 로그인한 계정이 표시됩니다. 수락하면 새 계정으로 로그인이 바뀌니, 다른 사람에게 보낼 링크라면 수락하지 말고 링크만 전달하세요.
</Tab>
<Tab title="이미 계정이 있을 때">
<Steps>
<Step title="초대받은 계정으로 로그인한다">
'해당 계정으로 로그인'을 누르고 초대받은 이메일의 계정으로 로그인합니다. 다른 계정으로 로그인해 있다면 화면에 현재 로그인한 계정이 표시되니 로그아웃한 뒤 진행하세요.
</Step>
<Step title="돌아와 수락한다">
로그인하면 초대 화면으로 돌아옵니다. '초대 수락하고 도입사로 이동'을 누르면 그 도입사의 '개요' 화면으로 이동합니다.
</Step>
</Steps>

이용 안내 동의가 남은 계정이면 '이용 안내 확인하고 초대 계속'이 먼저 나옵니다. 동의를 마치면 초대 수락으로 돌아옵니다.

로그인하러 간 뒤 30분 안에 돌아오지 않으면 '초대 링크를 다시 열어 주세요' 화면이 나옵니다. 대표관리자에게 받은 원래 링크를 다시 열면 이어서 수락할 수 있습니다.
</Tab>
</Tabs>

링크를 열었을 때 만료되었거나 이미 사용 또는 취소된 초대라는 안내가 나오면 대표관리자에게 새 초대를 요청하세요.

<Tip>
사용 중인 도입사에 아직 소속되지 않은 계정이 링크를 열지 않고 먼저 로그인하면 '도입사 선택' 화면이 나옵니다. 받은 초대 링크를 다시 열어 수락하세요.
</Tip>

### 계정을 직접 만들어 추가하기

<Steps>
<Step title="계정을 만든다">
'사용자 관리' 화면의 '계정 직접 생성'에서 '사용자 이메일', '이름', '초기 비밀번호', '업무 권한'을 넣고 '사용자 계정 생성'을 누릅니다. 초기 비밀번호는 8자 이상 72자 이하이고 한글은 1자를 3자로 계산합니다.
</Step>
<Step title="로그인 정보를 전달한다">
이메일과 초기 비밀번호를 본인에게 안전하게 전달합니다. MeterEngine은 메일을 보내지 않습니다.
</Step>
<Step title="본인이 첫 로그인을 마친다">
본인이 처음 로그인하면 '계정 이용 안내 확인' 화면이 나옵니다. '새 비밀번호'와 '새 비밀번호 확인'에 초기 비밀번호와 다른 비밀번호를 넣고 '이용 안내'와 '개인정보 처리 안내'에 체크한 뒤 '동의하고 업무 시작'을 누르면 업무를 시작할 수 있습니다. 이때부터 초기 비밀번호는 쓸 수 없고, 다른 곳에서 연 이 계정의 로그인도 끝납니다.
</Step>
</Steps>

첫 로그인 동의를 마치기 전에는 업무 요청이 `403 consent_required`로 거절됩니다.

## 초대 이력

대표관리자는 '사용자 관리' 화면의 '초대 이력'에서 발급한 초대를 봅니다.

| 상태 | 뜻 |
| --- | --- |
| 초대 대기 | 아직 수락하지 않았고 48시간이 지나지 않았습니다. '초대 취소'할 수 있습니다 |
| 수락 완료 | 초대받은 사람이 수락했습니다 |
| 초대 취소 | 대표관리자가 취소했거나, 그 이메일의 소속을 보관하면서 함께 취소됐습니다 |
| 만료 | 수락하지 않은 채 48시간이 지났습니다 |

만료, 수락 완료, 초대 취소 상태의 초대는 다시 쓸 수 없습니다. 다시 초대하려면 새로 발급합니다.

## 권한과 역할 바꾸기

대표관리자는 '도입사 사용자' 목록에서 사용 중인 구성원마다 아래 동작을 할 수 있습니다. 바꾼 권한은 그 구성원이 이미 로그인해 있어도 다음 요청부터 적용됩니다.

| 동작 | 하는 일 |
| --- | --- |
| 권한 변경 | 대표관리자가 아닌 구성원의 업무 권한을 바꿉니다. 전체 관리 (admin)를 넣고 빼면 역할도 관리자와 일반 사용자 사이에서 바뀝니다 |
| 역할 변경 | 역할을 대표관리자 또는 관리자로 바꿉니다. 두 역할 모두 업무 권한이 전체 관리 (admin)로 바뀌고 이전 권한은 남지 않습니다 |
| 소속 보관 | 이 도입사에 대한 접근을 중단합니다('접근 중단하고 보관') |

- 구성원을 대표관리자로 만들려면 먼저 초대나 계정 생성으로 추가한 뒤 '역할 변경'으로 바꿉니다. 초대 링크로 바로 대표관리자를 만들 수는 없습니다.
- 대표관리자를 일반 사용자로 바꾸려면 '역할 변경'으로 관리자로 바꾼 뒤 '권한 변경'으로 전체 관리 (admin)를 뺍니다.
- 대표관리자의 업무 권한에서는 전체 관리 (admin)를 뺄 수 없습니다(`409 owner_scopes_required`).

<Warning>
도입사에는 대표관리자가 적어도 한 명 있어야 합니다. 마지막 대표관리자는 다른 역할로 바꾸거나 소속을 보관할 수 없습니다(`409 last_owner_required`). 담당자가 바뀔 때는 새 담당자를 먼저 대표관리자로 만든 뒤 이전 담당자를 바꾸세요.
</Warning>

### 소속 보관

소속을 보관하면 그 구성원은 이 도입사에 더 접근할 수 없고, 이 도입사를 열어 둔 그 사람의 로그인은 바로 끝납니다. 그 사람이 남긴 업무와 감사 기록은 그대로 남고, 그 이메일로 발급해 둔 초대 대기 상태의 초대도 함께 취소됩니다.

API 키는 사람이 아니라 도입사에 속하므로 그 사람이 발급한 키는 소속을 보관해도 계속 쓸 수 있습니다. 그 사람이 키 원문을 알고 있다면 [키 교체, 권한 변경, 폐기](/authentication/key-rotation)를 보고 교체하거나 폐기하세요. 보관한 구성원을 다시 들이려면 같은 이메일로 초대 링크를 새로 발급해 수락받습니다. 이때 권한은 새 초대에 정한 권한이 됩니다.

보관된 소속은 '도입사 사용자' 목록 위의 '사용 중', '보관됨', '전체' 가운데 '보관됨'을 골라 봅니다.

## 여러 도입사에 속할 때

한 계정은 초대를 받아 여러 도입사에 속할 수 있습니다.

- 로그인하면 소속된 도입사 가운데 가장 먼저 소속된 사용 중인 도입사로 들어갑니다.
- 다른 도입사로 옮기려면 콘솔 위의 도입사 이름을 눌러 '도입사 선택' 화면으로 갑니다. '접근할 도입사'에서 도입사를 고르고 '도입사로 이동'을 누릅니다.
- 역할과 업무 권한은 도입사마다 따로입니다. 한 도입사에서 대표관리자여도 다른 도입사에서는 일반 사용자일 수 있습니다.
- 사용 중이 아닌 도입사(승인 대기, 가입 거절, 이용 정지)로는 업무를 할 수 없습니다. 상태의 뜻은 [가입과 승인](/account/signup)을 보세요.

## 오류

| code | 상황 |
| --- | --- |
| `409 email_already_exists` | 계정 직접 생성에 이미 계정이 있는 이메일을 넣었다. 초대 링크로 추가합니다 |
| `409 organization_member_already_exists` | 이미 이 도입사에 소속된 사용자를 초대하거나, 그 사용자가 초대를 수락하려 했다 |
| `409 invitation_unavailable` | 만료됐거나 이미 수락 또는 취소된 초대다 |
| `404 invitation_not_found` | 링크가 잘못됐거나 이 도입사에 없는 초대다 |
| `409 last_owner_required` | 마지막 대표관리자의 역할을 바꾸거나 소속을 보관하려 했다 |
| `409 owner_scopes_required` | 대표관리자의 권한에서 전체 관리 (admin)를 빼려 했다 |
| `403 consent_required` | 첫 로그인 동의를 마치지 않은 계정이다 |
| `403 permission_denied` | 대표관리자가 아닌 구성원이 사용자나 초대를 관리하려 했거나, 초대받은 이메일이 아닌 계정으로 수락하려 했다 |

오류 응답의 형식과 처리 방법은 [오류 응답과 X-Request-ID](/api-basics/errors)를 보세요.
