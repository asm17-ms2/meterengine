# 가이드 문체와 표기 규칙

- 이 파일은 공개하지 않는다(.mintignore). 공개되는 MDX를 쓰는 사람과 에이전트가 따른다.
- 여러 페이지에 걸치는 사실의 정본 페이지는 같은 폴더의 `canonical.md`를 본다.

## [1] 무엇을 쓰나

1. 지금 코드의 동작만 쓴다. 앞으로 생길 기능, 계획, 예정은 쓰지 않는다.
2. 내부 구현을 쓰지 않는다: 클래스 이름, 테이블 이름, 파일 경로, 줄 번호, 서버 설정 키, 환경변수 이름.
3. Jira 키, PR 번호, Discussion 번호, 팀 내부 사정(담당자, 회의, 일정)을 본문에 쓰지 않는다.
4. 목록을 세어 개수를 쓰지 않는다("10종", "5개", "다섯 가지"). 설정된 상한값은 쓴다(배치 100건, 수신처 10개, 48시간, 35일).
5. 한 사실은 정본 페이지 한 곳에만 자세히 쓰고 다른 곳은 한 줄 요약과 링크만 둔다.
6. 한국어로 쓴다. 독자는 MeterEngine을 자사 서비스 과금에 붙이는 조직의 개발자와 운영자다. 독자를 부르는 말은 [7]을 따른다. 존댓말 "~합니다", "~하세요"로 쓴다. 동사로 끝나는 Step, Accordion 제목도 "~합니다"로 쓴다(예: "업무 환경을 고릅니다"). 명사로 끝나는 제목은 그대로 둔다.
7. 콘솔 화면과 다르게 동작하는 곳은 지금 동작을 쓰고, 화면 문구와 다르다는 점을 Note 한 줄로 적는다(화면 문구를 그대로 인용해 따르게 하지 않는다).

## [2] 금지 문자와 문체

- 쓰지 않는다: 가운뎃점, 엠 대시, 엔 대시, 이모지, 둥근 따옴표. 하이픈, 쉼표, 콜론, 곧은 따옴표로 바꾼다.
- 한영 병기는 고유 제품명이 처음 나올 때만 한다(예: 토스페이먼츠(Toss Payments)는 쓰지 않아도 된다. 필요하면 첫 등장 한 번).
- "~일 수 있습니다", "~로 보입니다", "참고로" 같은 군말을 빼고 읽어 뜻이 같으면 뺀 채로 둔다.
- AI가 쓴 티가 나는 문구를 쓰지 않는다: "강력한", "손쉽게", "원활한", "~를 통해 ~할 수 있습니다"의 반복, 문단마다 붙는 요약 문장.
- Notion을 근거로 쓰지 않는다.

## [3] 링크

- docs.json에 있는 페이지 경로만 링크한다. 앞에 / 를 붙인 절대 경로로 쓴다(예: `/concepts/environments`). 확장자 `.mdx`를 붙이지 않는다.
- 없는 페이지를 링크하지 않는다. 아직 "작성 중"인 자리 페이지는 링크해도 된다(docs.json에 있으므로).
- API 참조는 `/api-reference/introduction`만 링크한다. 개별 엔드포인트 페이지 경로는 추측해 쓰지 않는다. 엔드포인트는 본문에 메서드와 경로로 쓴다(예: `POST /v1/events`).
- 문서 사이트 도메인(mintlify.site, docs.meterengine.com)을 본문에 쓰지 않는다. 빠른 시작의 코딩 어시스턴트 프롬프트에서 `llms.txt` 주소를 쓰는 것만 예외다.
- 다른 페이지를 가리킬 때는 "~을 참고하세요"로 쓴다("~을 보세요", "~을 봅니다"는 쓰지 않는다).
- 외부 링크는 토스페이먼츠 공식 문서, Standard Webhooks 사양처럼 1차 출처만 쓴다.

## [4] 예시 코드

- 주소는 `https://meterengine.com/v1/...`를 쓴다. staging 주소를 쓰지 않는다.
- API 키 자리표시자는 `{API_KEY}`를 쓴다(예: `Authorization: Bearer {API_KEY}`). MDX가 중괄호를 식으로 읽으므로 코드 블록이나 인라인 코드 안에만 쓴다. 라이브 키 예시(me_live_)는 쓰지 않는다.
- curl을 기본으로 쓴다. 필요하면 Node(fetch) 예시를 CodeGroup으로 붙인다. 다른 언어 예시는 쓰지 않는다.
- 요청 본문과 응답 예시의 필드 이름과 값의 형식은 DTO와 `backend/openapi.yaml`에서 확인한 그대로 쓴다. 필드를 만들어 넣지 않는다.
- UUID 예시는 형식이 맞는 값을 쓰고 페이지 안에서 같은 자원에는 같은 값을 쓴다.
- 시각 예시는 오프셋을 붙인 ISO 8601(`2026-11-05T10:00:00+09:00`)로 쓴다.
- SDK 이름이나 패키지 이름을 쓰지 않는다. demo 코드를 링크하지 않는다.

## [5] MDX 형식

- frontmatter에 `title`, `description`을 둔다. description은 한 문장이다.
- 쓰는 컴포넌트: Steps/Step, CodeGroup, Tabs/Tab, Note, Tip, Danger, Info, Check, Card/CardGroup, AccordionGroup/Accordion, ResponseField, Expandable, mermaid 코드 블록. 사용법이 불확실하면 https://www.mintlify.com/docs 를 확인한다.
- 되돌릴 수 없는 동작(이벤트 전송, 발행, 결제, 폐기)은 그 단계 바로 앞에 Danger(빨간색)를 둔다. Warning(노란색)은 쓰지 않는다. Danger를 한 페이지에 남발하지 않는다.
- 팀이 아직 정하지 않은 것에 기대는 문장 바로 앞에 `{/* 확인 필요: 내용 */}`을 단다. 공개 화면에는 보이지 않는다. 정해지면 문장을 맞추고 주석을 지운다.
- 단계마다 하는 곳을 밝힌다: 콘솔 화면에서 하는지, API로 하는지. 빠른 시작은 [화면], [API] 표시를 쓴다.
- 콘솔 로그인으로만 되는 기능 페이지는 상단에 Note "이 기능은 콘솔에 로그인한 상태에서만 됩니다. API 키로 부르면 거절됩니다."를 둔다.

## [6] 화면 표기 대응

화면 이름과 메뉴 이름, 버튼 이름은 아래 표기를 그대로 쓴다. 따옴표는 곧은 작은따옴표로 감싼다(예: '테스트 환경'). 출처는 frontend 코드의 문구다(2026-11-17 기준). 화면 문구가 바뀌면 이 표부터 고친다.

### 업무 환경

| API 값 | 화면 표기 | 가이드에서 쓰는 말 | 비고 |
| --- | --- | --- | --- |
| test | 테스트 환경 | 테스트 환경 | "샌드박스"라고 부르지 않는다 |
| live | 라이브 환경 | 라이브 환경 | "운영 환경", "프로덕션"이라고 쓰지 않는다 |
| legacy | 기존 데이터 | 기존 데이터 | API 헤더 값 legacy는 웹훅 environment 값 설명에서만 쓴다 |
| (선택 상자 이름) | (글씨 없이 선택 상자만 보인다) | 업무 환경 | 화면 위 선택 상자. 바꾸면 확인 창의 '전환'을 누른다. 라이브 환경이 잠긴 조직에는 '라이브 환경 (승인 전)'으로 보이고, 고르면 확인 창의 '이동'으로 이용 신청 화면에 간다. 테스트 환경과 라이브 환경을 묶어 부를 때도 '업무 환경'이라고 쓴다 |
| (콘솔 맨 위 띠) | 테스트 환경이에요. 실제 결제와 청구가 일어나지 않아요. / 라이브 환경이에요. 고객에게 실제로 청구하고 결제해요. | 화면 맨 위 띠 | 화면 맨 위에 고정된 띠. 테스트 환경은 노랑, 라이브 환경은 빨강이다. 환경 안내는 이 띠를 가리킨다 |

## [7] 용어

| 쓰는 말 | 쓰지 않는 말 | 비고 |
| --- | --- | --- |
| 조직 | 도입사, 테넌트, 고객사 | 화면 표기와 같다(조직 설정, 조직 선택, 조직 이름). 가입으로 만들어지는 단위를 가리킬 때 쓴다. API 경로와 필드의 organization은 그대로 둔다 |
| 자사 서버, 자사 시스템, 자사 서비스 | 도입사 서버, 도입사 시스템 | 독자가 운영하는 쪽을 가리킨다. 콘솔 문구 '자사 서비스'와 맞춘다 |
| (독자를 주어로 쓰지 않음) | 도입사가, 도입사는 | 독자가 할 일은 주어 없이 "~합니다", "직접 ~합니다", "콘솔에서 ~합니다"로 쓴다. MeterEngine과 나란히 견줄 때만 '조직'을 쓴다 |
| 고객 | 사용자, 회원 | 조직이 청구하는 상대 |
| 구성원, 사용자 | 멤버 | 콘솔에 로그인해 조직의 업무를 하는 사람. 메뉴는 '사용자 관리' |
| 과금 미터 | 빌러블 메트릭, 지표 | 화면 표기 |
| 단가, 요금제 | 가격표, 플랜 | |
| 청구 예정액 | 드래프트, 초안 청구서 | |
| 청구액, 청구서 금액 | 발행 청구액, 발행액, 발행 금액 | 발행한 청구서의 금액. 홈의 금액 칸과 그래프는 '청구액'이고, 문장에서는 '청구서 금액'이라고 쓴다 |
| 청구서, 발행한 청구서 | 인보이스, 발행 청구서 | 화면 표기와 같다. 메뉴와 화면 제목은 '청구서'이고, 문장에서 발행을 밝힐 때는 '발행한 청구서'라고 쓴다. 가이드 전체에서 한 번(용어 대응표) '청구서(API의 invoice)'라고 적는다. 코드, API 경로, 필드 이름은 그대로 둔다 |
| 발행, 발행한 청구서 | 확정, 확정 청구서 | 청구서의 금액을 굳히는 일. 화면 표기와 같다. API의 `finalize`, `finalized_at` 같은 이름은 그대로 둔다 |
| 웹훅 | 통보, 알림 | 화면 표기와 같다(메뉴 'API 키와 웹훅', 입력란 '웹훅 URL', 선택지 '테스트 웹훅') |

| 테스트 웹훅 | 시험 발송, 시험 이벤트 | 화면 '테스트 웹훅 보내기'와 같다 |

| 부가세 포함 금액 | 세금 포함 금액 | 화면 표기와 같다 |
| 과금 제외 사용량 | 청구 제외 사용량, 청구에서 빠진 사용량 | 웹훅 선택지 이름과 같다 |
| 과금 미터 코드, 집계 함수, 끝수 처리, 과금 수량 | 과금 미터 code, 집계 방식, 반올림(끝수 처리 전체를 가리킬 때), 청구 수량 | 화면 표기와 같다 |
| 업무 환경 | 워크스페이스 환경, 모드, 결제 모드(콘솔을 말할 때) | API 키의 모드는 "테스트 키인지 라이브 키인지"로 쓴다 |
| 결제 모드 | PG 모드 | API 필드 `mode`를 설명할 때만 쓴다. 콘솔은 결제 모드를 따로 부르지 않고 '업무 환경'(열 이름, 값 '테스트 환경', '라이브 환경')으로 보인다 |
| 라이브 환경, 라이브 키 | 실제 환경, 운영 환경, 운영 키 | 화면 표기와 같다 |
| 구분 키, 구분 값 | 차원 키, 차원 값, 조합 | 화면 표기와 같다. API의 `dimension_properties`, `dimension_values`는 그대로 둔다 |
| KST | Asia/Seoul | 시각은 "2026-11-02 04:00 KST"처럼 쓴다 |
| batch | 묶음, 묶어 보내기, 배치 | `POST /v1/event-batches`로 여러 이벤트를 한 요청에 보내는 것. "batch로 보내기", "batch 요청", "batch 결과"처럼 쓴다. 콘솔 열 이름 '묶음 안 순서'는 화면 표기라 그대로 둔다 |
| 테스트 화면 | 시험 화면 | API 참조 엔드포인트 페이지의 '시도하기'로 여는 요청 화면. 테스트 환경, 테스트 키와 같은 '테스트'로 맞춘다 |
| 기본료, 최소 사용료 | 월 기본료, 월 최소 사용료(본문) | 화면 입력란 '월 기본료 (원)', '월 최소 사용료 (원)'을 인용할 때만 '월'을 붙인다 |
| 영문 표기 | API 값 | 용어 대응표와 표의 열 이름. API의 필드 이름, 값, 경로 이름을 적는다 |
