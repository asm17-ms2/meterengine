---
title: "빠른 시작"
description: "가입부터 테스트 환경에서 사용량 이벤트를 보내 청구 예정액을 확인하기까지, 콘솔이나 API 가운데 편한 쪽으로 따라 합니다."
---

이 페이지를 따라 하면 테스트 환경에 미터와 단가를 만들고, 고객 한 명에게 사용량 이벤트 두 건을 보내 청구 예정액 2,000원을 확인합니다. 시작하는 방법은 세 가지입니다.

- **콘솔에서 시작**: 미터, 단가, 고객을 콘솔 화면에서 만들고 이벤트만 API로 보냅니다. 처음 써 본다면 이 방법을 권합니다.
- **API로 시작**: API 키 발급만 콘솔에서 하고 나머지를 모두 API로 합니다.
- **코딩 어시스턴트로 시작**: 쓰고 있는 코딩 어시스턴트에게 아래 프롬프트를 붙여 넣어 API로 시작하는 단계를 맡깁니다.

단계 제목의 [화면]은 브라우저에서 콘솔 https://meterengine.com 에 로그인해 하는 일, [API]는 자사 서버나 터미널에서 HTTP 요청을 보내는 일입니다. 준비물은 메일을 받을 수 있는 이메일 주소, 그리고 curl 또는 Node.js 18 이상입니다.

{/* 확인 필요: 공개 API 주소 */}
API는 콘솔과 같은 도메인의 `https://meterengine.com/v1/` 아래에 있고, 어느 환경에 기록될지는 API 키가 정합니다. 이 페이지의 단계는 모두 테스트 환경에서 하니, 테스트 환경에서 발급한 키(`me_test_`로 시작)를 쓰세요.

{/* 확인 필요: 테스트 키 정의와 mode 설명 */}
<Danger>
테스트 환경도 보낸 이벤트와 발행한 청구서는 되돌릴 수 없습니다. 이벤트가 들어온 미터는 이름만 바꿀 수 있고 계산 기준을 바꿀 수 없습니다. 이 페이지의 미터 코드, 이벤트 유형, 고객 외부 ID는 빠른 시작 전용 값이니, 실제 연동에 쓸 이름을 여기에 쓰지 마세요. 테스트 환경의 뜻은 [업무 환경](/concepts/environments), 미터의 제약은 [미터 설계](/pricing/meters)를 참고하세요.
</Danger>

## 가입과 로그인

<Steps>
  <Step title="[화면] 가입합니다">
    https://meterengine.com/signup 의 '가입' 화면에서 조직 이름, 담당자 이름, 이메일, 비밀번호를 입력하고 '이용약관에 동의합니다 (필수)'와 '개인정보 처리방침을 확인했습니다 (필수)'에 체크한 뒤 '가입'을 누릅니다. 입력 규칙과 오류는 [가입과 이메일 인증](/account/signup)을 참고하세요.
  </Step>
  <Step title="[화면] 이메일을 인증합니다">
    '메일함을 확인하세요' 화면이 나오면 가입한 이메일로 온 인증 메일의 '이메일 인증하기'를 열고 '이메일 인증'을 누릅니다.
  </Step>
  <Step title="[화면] 로그인합니다">
    https://meterengine.com/login 에서 가입한 이메일과 비밀번호로 로그인하면 '홈' 화면이 열립니다. 가입한 사람은 그 조직의 대표관리자가 됩니다.

    화면 위 '업무 환경'이 '테스트 환경'인지 확인하세요. 로그인하면 테스트 환경으로 열립니다.
  </Step>
</Steps>

## 시작 방법 고르기

<Tabs>
<Tab title="콘솔에서 시작">
<Steps>
  <Step title="[화면] 미터를 만듭니다">
    왼쪽 메뉴 '미터' 화면에서 '미터 등록'을 누르고 아래처럼 입력한 뒤 '저장'을 누릅니다.

    | 입력란 | 값 |
    | --- | --- |
    | 코드 | `quickstart-api-calls` |
    | 이름 | `빠른 시작 API 호출` |
    | 이벤트 유형 | `quickstart_api_call` |
    | 집계 함수 | '합계' |
    | 집계 대상 속성 | `units` |
    | 구분 키 | 비워 둡니다 |
    | 과금 단위 크기 | `1` (기본값) |
    | 끝수 처리 | '추가 반올림 없음' (기본값) |

    이 미터는 `type`이 `quickstart_api_call`인 이벤트의 `properties.units` 값을 더해 과금 수량으로 씁니다. 미터 코드는 등록 뒤 바꿀 수 없습니다.
  </Step>
  <Step title="[화면] 이번 달 단가를 등록합니다">
    왼쪽 메뉴 '요금 설정' 화면의 '무엇을 과금하나요'에서 '빠른 시작 API 호출'을 고르고 '단가 버전 등록'을 누릅니다. 창 위에 '모든 고객 공통'이 보이는지 확인하고 아래처럼 입력한 뒤 창 아래의 '단가 버전 등록'을 누릅니다.

    | 입력란 | 값 |
    | --- | --- |
    | 적용 시작 월 | 이번 달 (기본값) |
    | 적용 종료 월 (선택) | 비워 둡니다 |
    | 단가 모델 | '단일 단가: 수량에 같은 단가 적용' |
    | 과금 수량 1당 단가 (원) | `100` |

    단가는 이번 달 이후에만 넣을 수 있습니다. 단가가 없으면 이벤트를 보내도 청구 예정액이 0원입니다.
  </Step>
  <Step title="[화면] 고객을 등록합니다">
    왼쪽 메뉴 '고객' 화면에서 '고객 등록'을 누르고 '고객명'에 `빠른 시작 고객`, '외부 고객 ID'에 `quickstart-customer-1`을 넣은 뒤 '등록'을 누릅니다.

    목록에서 고객 이름을 눌러 상세 화면을 열면 주소가 `/customers/<고객 id>?month=...` 형태입니다. `/customers/` 뒤부터 `?` 앞까지가 고객 id(UUID)이니 복사해 둡니다. 이벤트의 `customer_id`에는 외부 고객 ID가 아니라 이 id를 넣습니다.
  </Step>
  <Step title="[화면] API 키를 발급합니다">
    왼쪽 메뉴 'API 키와 웹훅' 화면의 'API 키'에서 'API 키 발급'을 누릅니다. '키 이름'에 `빠른 시작`을 넣고, 'API 권한'은 '조회 (read)'에 더해 '수집 (ingest)'도 체크한 뒤 'API 키 발급'을 누릅니다. 나온 키를 'API 키 복사'로 복사해 둡니다.

    <Danger>
    키 원문은 발급 직후 한 번만 보이니 바로 비밀 저장소에 옮깁니다. 창을 닫으면 다시 볼 수 없습니다.
    </Danger>
  </Step>
  <Step title="[API] 사용량 이벤트를 보냅니다">
    이벤트는 API로만 보냅니다. 아래 예시의 `{API_KEY}`를 복사한 키로, `customer_id`를 앞에서 복사한 고객 id로 바꿔 보냅니다.

    `POST /v1/events`로 이벤트 두 건을 보냅니다. 첫 건은 `units` 12, 둘째 건은 `transaction_id`를 `quickstart-tx-002`로, `units`를 8로 바꿔 한 번 더 보냅니다.

    <CodeGroup>
    ```bash curl
    curl -X POST https://meterengine.com/v1/events \
      -H "Authorization: Bearer {API_KEY}" \
      -H "Content-Type: application/json" \
      --data @- <<EOF
    {
      "transaction_id": "quickstart-tx-001",
      "customer_id": "3f6c2a1e-8b4d-4c7a-9e2f-5d1b7a9c0e42",
      "type": "quickstart_api_call",
      "timestamp": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
      "properties": { "units": 12 }
    }
    EOF
    ```

    ```javascript Node
    const response = await fetch("https://meterengine.com/v1/events", {
      method: "POST",
      headers: {
        Authorization: "Bearer {API_KEY}",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        transaction_id: "quickstart-tx-001",
        customer_id: "3f6c2a1e-8b4d-4c7a-9e2f-5d1b7a9c0e42",
        type: "quickstart_api_call",
        timestamp: new Date().toISOString(),
        properties: { units: 12 },
      }),
    });
    console.log(response.status, await response.json());
    ```
    </CodeGroup>

    `timestamp`는 사용량이 생긴 시각이고 지금 시각을 넣었습니다. 받으면 202와 함께 아래 응답이 옵니다. 저장은 뒤에서 합니다. 요청 안에서 저장까지 마치면 200과 `"duplicate": false`가 오기도 하며, 이 경우도 정상입니다.

    ```json
    {"transaction_id": "quickstart-tx-001"}
    ```

    - `type`은 미터의 이벤트 유형과 글자까지 같아야 집계됩니다.
    - `units`는 따옴표 없는 숫자로 보냅니다. `"12"`처럼 문자열로 보내면 저장은 되지만 합계에서 빠집니다.
    - 같은 `transaction_id`로 다시 보내면 처음 것이 남습니다. 200으로 답할 때는 응답의 `duplicate`가 `true`입니다. 규칙은 [멱등 규칙](/api-basics/idempotency)에 있습니다.

    이벤트 형식과 batch로 보내기는 [사용량 이벤트 보내기](/integration/events)에 있습니다.
  </Step>
  <Step title="[화면] 청구 예정액을 확인합니다">
    왼쪽 메뉴 '청구 검토' 화면을 열면 '빠른 시작 고객'의 이번 달 청구 예정액이 2,000원으로 보입니다. 두 이벤트의 `units` 합 20에 단가 100원을 곱한 값입니다.

    <Check>
    청구 예정액이 2,000원이면 빠른 시작을 마친 것입니다.
    </Check>
  </Step>
</Steps>
</Tab>
<Tab title="API로 시작">
<Steps>
  <Step title="[화면] API 키를 발급합니다">
    API 키 발급은 콘솔에서만 합니다. 왼쪽 메뉴 'API 키와 웹훅' 화면의 'API 키'에서 'API 키 발급'을 누릅니다.

    1. '키 이름'에 `빠른 시작`처럼 알아볼 이름을 넣습니다.
    2. 'API 권한'은 '조회 (read)'만 체크되어 있습니다. '수집 (ingest)'와 '전체 관리 (admin)'도 체크합니다. 미터와 단가 등록에는 admin, 고객 등록과 이벤트 전송에는 ingest, 청구 예정액 조회에는 read가 필요합니다.
    3. '분당 요청 한도'는 비워 둡니다. 테스트 키에는 비워 두어도 테스트 환경 한도가 걸립니다([요청 한도와 429](/api-basics/rate-limits)).
    4. 'API 키 발급'을 누르고, 나온 키를 'API 키 복사'로 복사해 안전한 곳에 저장합니다.

    테스트 환경에서 발급한 키는 `me_test_`로 시작하고 테스트 환경에 고정되어, 요청에 환경 헤더를 따로 넣지 않아도 됩니다. 아래 예시의 `{API_KEY}`를 방금 복사한 키로 바꿔 보내세요.

    <Danger>
    키 원문은 발급 직후 한 번만 보이니 바로 비밀 저장소에 옮깁니다. 창을 닫으면 다시 볼 수 없습니다. 빠른 시작이 끝나면 admin 권한은 '키 권한 변경'으로 빼 두세요.
    </Danger>
  </Step>
  <Step title="[API] 미터를 만듭니다">
    `POST /v1/billable-metrics`로 미터를 만듭니다. 처음 등록하면 201이 옵니다.

    ```bash curl
    curl -X POST https://meterengine.com/v1/billable-metrics \
      -H "Authorization: Bearer {API_KEY}" \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: quickstart-metric" \
      -d '{
        "code": "quickstart-api-calls",
        "name": "빠른 시작 API 호출",
        "event_type": "quickstart_api_call",
        "aggregation": "sum",
        "target_property": "units"
      }'
    ```

    이 미터는 `type`이 `quickstart_api_call`인 이벤트의 `properties.units` 값을 더해 과금 수량으로 씁니다. 필드는 [미터 설계](/pricing/meters)를 참고하세요.
  </Step>
  <Step title="[API] 이번 달 단가를 등록합니다">
    `POST /v1/billable-metrics/{code}/price-rates`로 모든 고객에게 쓰는 단가 100원을 등록합니다. 구분 키가 없는 미터라 `dimension_values`는 빈 객체입니다. `effective_from`을 생략하면 이번 달부터 적용됩니다.

    ```bash curl
    curl -X POST https://meterengine.com/v1/billable-metrics/quickstart-api-calls/price-rates \
      -H "Authorization: Bearer {API_KEY}" \
      -H "Content-Type: application/json" \
      -d '{"dimension_values": {}, "model": "per_unit", "unit_price": 100}'
    ```

    단가 방식은 [단가 모델과 버전](/pricing/price-models)을 참고하세요.
  </Step>
  <Step title="[API] 고객을 등록합니다">
    `POST /v1/customers`로 고객을 등록합니다. `external_id`에는 자사 시스템의 고객 ID를 넣습니다.

    <CodeGroup>
    ```bash curl
    curl -X POST https://meterengine.com/v1/customers \
      -H "Authorization: Bearer {API_KEY}" \
      -H "Content-Type: application/json" \
      -d '{"external_id": "quickstart-customer-1", "name": "빠른 시작 고객"}'
    ```

    ```javascript Node
    const response = await fetch("https://meterengine.com/v1/customers", {
      method: "POST",
      headers: {
        Authorization: "Bearer {API_KEY}",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({ external_id: "quickstart-customer-1", name: "빠른 시작 고객" }),
    });
    console.log(response.status, await response.json());
    ```
    </CodeGroup>

    Node 예시는 최상위 `await`를 쓰므로 `.mjs` 파일로 저장해 실행합니다. 처음 등록하면 201과 함께 등록된 고객이 옵니다.

    ```json
    {
      "id": "3f6c2a1e-8b4d-4c7a-9e2f-5d1b7a9c0e42",
      "name": "빠른 시작 고객",
      "billing_email": null,
      "created_at": "2026-11-05T01:00:00Z",
      "external_id": "quickstart-customer-1",
      "archived_at": null,
      "version": 0
    }
    ```

    응답의 `id`를 저장하세요. 이벤트의 `customer_id`에는 외부 고객 ID가 아니라 이 `id`(UUID)를 넣습니다. 같은 `external_id`로 다시 보내면 새 고객을 만들지 않고 기존 고객을 200으로 돌려주므로, `id`를 잃었으면 같은 요청을 다시 보내면 됩니다. 자세한 내용은 [고객 등록과 ID 대응](/integration/customers)에 있습니다.
  </Step>
  <Step title="[API] 사용량 이벤트를 보냅니다">
    `POST /v1/events`로 이벤트 두 건을 보냅니다. 첫 건은 `units` 12, 둘째 건은 `transaction_id`를 `quickstart-tx-002`로, `units`를 8로 바꿔 한 번 더 보냅니다. `customer_id`는 앞 단계에서 받은 `id`로 바꿉니다.

    <CodeGroup>
    ```bash curl
    curl -X POST https://meterengine.com/v1/events \
      -H "Authorization: Bearer {API_KEY}" \
      -H "Content-Type: application/json" \
      --data @- <<EOF
    {
      "transaction_id": "quickstart-tx-001",
      "customer_id": "3f6c2a1e-8b4d-4c7a-9e2f-5d1b7a9c0e42",
      "type": "quickstart_api_call",
      "timestamp": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
      "properties": { "units": 12 }
    }
    EOF
    ```

    ```javascript Node
    const response = await fetch("https://meterengine.com/v1/events", {
      method: "POST",
      headers: {
        Authorization: "Bearer {API_KEY}",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        transaction_id: "quickstart-tx-001",
        customer_id: "3f6c2a1e-8b4d-4c7a-9e2f-5d1b7a9c0e42",
        type: "quickstart_api_call",
        timestamp: new Date().toISOString(),
        properties: { units: 12 },
      }),
    });
    console.log(response.status, await response.json());
    ```
    </CodeGroup>

    ```json

    ```

    - `type`은 미터의 이벤트 유형과 글자까지 같아야 집계됩니다.
    - `units`는 따옴표 없는 숫자로 보냅니다. `"12"`처럼 문자열로 보내면 저장은 되지만 합계에서 빠집니다.

## 결과가 다를 때

응답의 `code`로 원인을 고릅니다. 오류 형식은 [오류 응답과 X-Request-ID](/api-basics/errors), 원인을 찾는 순서는 [이벤트가 청구에 안 보일 때](/troubleshooting/events-not-billed)에 있습니다.

<AccordionGroup>
  <Accordion title="401 authentication_required 또는 invalid_credentials">
    `authentication_required`는 `Authorization` 헤더가 없을 때, `invalid_credentials`는 키의 형식이 틀렸거나 모르는 키이거나 폐기 또는 만료된 키일 때 옵니다. `Authorization: Bearer ` 뒤에 복사한 키 전체를 넣었는지 확인하세요.
  </Accordion>
  <Accordion title="403 permission_denied">
    키에 필요한 권한이 없습니다. 고객 등록과 이벤트 전송에는 ingest, 청구 예정액 조회에는 read가 필요합니다. 'API 키와 웹훅' 화면의 '키 권한 변경'으로 권한을 더하면 같은 키로 다음 요청부터 적용됩니다.
  </Accordion>
  <Accordion title="403 organization_not_active">
    조직의 이용이 정지된 상태입니다. 자세한 내용은 [가입과 이메일 인증](/account/signup)에 있습니다.
  </Accordion>
  <Accordion title="404 customer_not_found">
    `customer_id`가 가리키는 고객이 이 키의 업무 환경에 없습니다. 고객 등록 응답의 `id`를 넣었는지, 외부 고객 ID를 넣지 않았는지 확인하세요.
  </Accordion>
  <Accordion title="400 event_too_old">
    35일보다 오래된 이벤트는 거절됩니다. 같은 이벤트를 다시 보내도 받지 않습니다. `timestamp`에 지금 시각을 넣었는지 확인하세요. 기준은 [시간 규칙](/concepts/time-rules)에 있습니다.
  </Accordion>
  <Accordion title="200으로 저장됐는데 청구 예정액이 0원">
    이벤트는 저장됐지만 과금 수량이나 단가와 이어지지 않은 경우입니다. 다음을 차례로 봅니다.

    - 업무 환경: 미터와 단가를 '테스트 환경'에서 만들었는지 봅니다. 고객, 미터, 단가는 업무 환경마다 따로 만들어야 합니다.
    - 단가: 응답의 `unpriced_usages`에 사용량이 나오면 그 미터에 이번 달 단가가 없습니다.
    - 이벤트 유형: 이벤트의 `type`이 미터의 이벤트 유형과 다르면 어느 미터에도 집계되지 않습니다.
    - 속성 값: `units`를 문자열로 보냈거나 키 이름이 다르면 합계에서 빠집니다.
  </Accordion>
</AccordionGroup>

## 홈 화면의 준비 목록

{/* 확인 필요: 홈 체크리스트 완료 조건 */}
홈 화면의 '청구 전 준비' 목록(과금할 고객 연결, 사용량과 요금 정의, API 키 발급, 공급자와 결제 설정)은 진행 상황 표시입니다. 이 가이드는 금액이 바로 보이도록 미터와 단가를 먼저 만들고 고객과 이벤트를 보내는 순서로 안내합니다. 화면 순서대로 고객부터 등록해도 결과는 같습니다.

- '사용량과 요금 정의'는 미터를 하나 만들면 완료로 표시되지만 단가가 없으면 청구 예정액이 0원이니 단가도 등록했는지 확인하세요.
- '공급자와 결제 설정'은 빠른 시작에서 하지 않아도 됩니다. 토스페이먼츠 키는 결제를 요청할 때 필요하고, 공급자 정보가 쓰이는 곳은 [공급자 정보](/account/supplier)에 있습니다.
